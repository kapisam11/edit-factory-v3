# Autonomous YouTube operation

Edit Factory v3 includes an opt-in, single-host autonomous YouTube operating loop.

The loop persists the content queue in SQLite, researches topics, produces upload packages, checks rights/factuality/media readiness, rejects generic or repetitive scripts, schedules publication, uploads with duplicate protection, collects analytics, and feeds measured outcomes back into the channel-learning store.

## Human-quality guard

Autonomous publishing is blocked when the content looks too templated. The guard checks for repeated scripts, high n-gram similarity to recent uploads, filler/cliche openings, excessive clickbait, low specificity, and weak script/metadata quality.

The factory also removes accidental product/vendor boilerplate such as internal tool names or phrases like "created with AI" from public title/description/tag fields. It does not add an AI watermark or an "AI-generated by Edit Factory" credit.

This is not an attempt to evade platform disclosure rules. When realistic altered/synthetic media is present, the publisher sets YouTube's synthetic-media flag. AI/synthetic jobs cannot be claimed for upload until the disclosure decision is recorded. The dashboard's **Review disclosure & approve** action records an explicit review; fully unattended mode requires the separate `AIVF_AUTONOMOUS_DISCLOSURE_POLICY_ACKNOWLEDGED=1` opt-in, which acknowledges that the system will apply the configured platform flag according to each video's review flags. This never disables or conceals a required platform disclosure.

## Recommended rollout

Use the defaults first:

- AIVF_AUTONOMOUS_PUBLISH=0
- AIVF_AUTONOMOUS_REQUIRE_HUMAN_APPROVAL=1
- AIVF_AUTONOMOUS_DISCLOSURE_POLICY_ACKNOWLEDGED=0
- AIVF_MAX_VIDEOS_PER_DAY=2
- AIVF_MAX_CONSECUTIVE_FAILURES=3
- AIVF_YOUTUBE_PRIVACY=private

This produces packages and schedules them in READY/SCHEDULED, but requires dashboard approval before a public upload.

After you have reviewed several successful packages, fully unattended publication can be enabled explicitly:

    AIVF_AUTONOMOUS_PUBLISH=1
    AIVF_AUTONOMOUS_REQUIRE_HUMAN_APPROVAL=0
    AIVF_AUTONOMOUS_DISCLOSURE_POLICY_ACKNOWLEDGED=1
    AIVF_AUTONOMOUS_ALLOW_PUBLIC=1
    AIVF_YOUTUBE_PRIVACY=public
    AIVF_MAX_VIDEOS_PER_DAY=2
    AIVF_MAX_CONSECUTIVE_FAILURES=3
    AIVF_MAX_DAILY_COST_USD=5
    AIVF_ESTIMATED_COST_PER_VIDEO_USD=1
    AIVF_TOPIC_SEEDS=your niche seed|another seed
    AIVF_PUBLISH_TIMES_UTC=12:00,18:00

Keep the YouTube OAuth client secrets and refresh token outside the repository. The container service supports paths supplied through YOUTUBE_CLIENT_SECRETS and YOUTUBE_TOKEN_PATH.

## Dashboard controls

The WSGI application exposes admin-only controls:

- /api/autonomous/status
- /api/autonomous/queue
- /api/autonomous/enqueue
- /api/autonomous/approve/<job_id>
- /api/autonomous/pause
- /api/autonomous/resume
- /api/autonomous/emergency-stop
- /api/autonomous/clear-emergency-stop
- /api/autonomous/run-once

The dashboard role check is reused; these are not public unauthenticated endpoints.

## Docker

The compose file contains an automation profile. It is opt-in:

    docker compose --profile automation up -d autonomous-publisher

The service uses the same immutable digest-pinned image as the web application and shares the durable state/output volumes.

## Publishing guarantees

The publisher uses resumable uploads and a local idempotency record keyed from the finished video. Before a retry it checks the channel for an existing video with the same title and matching duration, and it also re-checks after an upload error. This reduces the classic "upload succeeded but the network died before the client saw the response" duplicate-video failure mode.

The queue has explicit IDEA -> PRODUCING -> READY -> SCHEDULED -> UPLOADING -> PUBLISHED -> ANALYZING -> ANALYZED lifecycle states plus failure/policy-review states.

## Economics and learning

The loop records a cost estimate for each production attempt in an append-only SQLite ledger; a transaction reserves the estimate before generation, so concurrent local daemons cannot spend the same daily budget headroom. Set `AIVF_ESTIMATED_COST_PER_VIDEO_USD` conservatively for the providers/models you use. This is a budget guard based on configured estimates, **not an exact billing meter**: provider usage/cost data is not available from every configured generator, so check provider billing dashboards as well. The loop also collects YouTube analytics, estimates revenue when the YouTube Analytics API permits it, computes daily ROI, and writes channel-level performance recommendations. Analytics failures are retried independently rather than regenerating the video.

No system can guarantee monetization, growth, or revenue. The engineering goal is to maximize the quality of videos produced per hour of human attention while keeping the system bounded and stoppable.

## Anti-slop and unattended safety defaults

The autonomous loop rejects repeated openings, repeated n-gram phrasing, canned/filler narration, repetitive vocabulary, excessive CTA language, low specificity, clickbait patterns, and near-duplicate topics. Future topic discovery also uses measured topic performance.

Set a narrow channel niche with:

    AIVF_CHANNEL_NICHE="your narrow topic area"

Topic-diversity protection defaults to:

    AIVF_MIN_TOPIC_VARIATION=0.72

Claims needing factual review stay in POLICY_REVIEW instead of being silently auto-approved:

    AIVF_AUTONOMOUS_REQUIRE_FACT_REVIEW=1

Stale scheduled items are moved to POLICY_REVIEW:

    AIVF_STALE_SCHEDULE_DAYS=14

Public autonomous publishing is disabled by default:

    AIVF_AUTONOMOUS_ALLOW_PUBLIC=0

The factory does not add its own product/vendor/AI-generator credit to public title, description, or tags, and does not add a factory watermark. This removes accidental factory boilerplate only; it does not remove source/rights information or suppress a YouTube-required altered/synthetic-media disclosure. AI credits in public prose are separate from YouTube's native disclosure: native disclosure remains enabled when required.

## YouTube authentication

The daemon never opens a browser unexpectedly. For first-time/manual authorization only:

    YOUTUBE_AUTH_INTERACTIVE=1

After a valid refresh token has been saved, keep the daemon setting at:

    YOUTUBE_AUTH_INTERACTIVE=0

Authentication refresh failures and YouTube quota/auth failures pause autonomous publishing and require operator action.
