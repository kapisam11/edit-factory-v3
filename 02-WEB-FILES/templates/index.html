Rendering

Protect valid video output

FFmpeg/FFprobe validation checks rendered media before it is accepted. Failed normalization or reruns should not silently replace the last valid final video.

Dashboard guide ↗
Jobs & recovery

Recoverable background work

Jobs record persistent state and attempts. Restart reconciliation and lease/attempt checks help prevent stale workers from claiming that an old run completed.

Architecture ↗
Release checks

Readiness reports tell the truth

The checker separates PASS, IMPLEMENTED, CI, ENVIRONMENT, MANUAL, and BLOCKED. A file existing is not proof that a behavior passed.

Readiness checker ↗
Windows

Development and production are separate

START-ALL.bat is for local development. START-PRODUCTION.bat uses the production Compose file, requires an immutable image digest, and keeps database migrations explicit.

Production setup ↗
Host protection

Conservative resource defaults

The dashboard binds to localhost by default. Job concurrency, container CPU/memory/PID limits, upload limits, and free-disk safeguards help protect a single Windows PC.

Setup & safety notes ↗
Publishing

Per-platform status and reconciliation

YouTube, TikTok Direct Post, and Instagram Reels adapters have separate destination state and retry handling. Mock tests do not prove account eligibility or a successful live post.

Publishing guide ↗
Rights & review

Evidence before publishing

Rights evidence and factuality checks support review, while human approval remains a separate gate. A credit or source URL alone does not prove permission to reuse content.

Rights & upload guide ↗
Verification

More Windows and pipeline checks

CI exercises the real Windows FFmpeg path, PowerShell launchers, media validation, dashboard flows, Docker builds, and security checks. Target-host and real-account acceptance are still separate.
